# Render deployment

This repository includes a Render Blueprint in [`render.yaml`](./render.yaml). After pushing it to GitHub:

1. In Render, create a new Blueprint and connect this repository.
2. Review the service plan and persistent disk before confirming. The blueprint uses a paid Standard web service in Singapore and a 1 GB persistent disk; Render will show its current charges.
3. Set `BASE_URL` and `ALLOWED_ORIGINS` to the actual public/custom domain after the Render hostname and DNS are known.
4. Enter integration credentials as secret environment variables in Render's dashboard. Do not commit credentials to this repository.
5. Confirm `/api/health` is healthy, then test signup, a template preview/builder, and checkout in test mode before enabling live payment credentials.

The JWT and admin secrets are generated by Render. Missing Google OAuth, payment, AI, media-storage, email, and monitoring credentials leave those integrations unavailable or in their existing fallback mode; a deployment alone does not activate third-party accounts or charge customers. Only configure live payment keys after the merchant account and webhook are ready.

## Persistence and scaling

The current application repository stores user and transaction records in `server/data/store.json`. The persistent disk is mounted at that directory so those records survive deploys and restarts. Keep this service to one instance: the JSON store is not a multi-instance database. Although the environment template mentions `DATABASE_URL`, the current repository implementation does not switch its core data store to PostgreSQL when that variable is set.

User-uploaded media must use configured Cloudinary or S3 credentials for durable storage. Files written to any other local directory are not covered by the data disk and may be lost when Render replaces the instance.

## Go-live checks

- Configure a real domain and matching `BASE_URL`/`ALLOWED_ORIGINS`.
- Configure the Google OAuth client and allow the production domain in its provider settings if Google sign-in is needed.
- Configure a live Razorpay or Cashfree account and webhook secret. Until then, production checkout is intentionally disabled rather than treated as live.
- Configure Gemini (or another supported AI provider), Cloudinary/S3, and an email provider if those features should be live.
- Check `/api/health` and make sure each integration reports the expected production status. Never paste private keys into GitHub issues, commits, or source files.
